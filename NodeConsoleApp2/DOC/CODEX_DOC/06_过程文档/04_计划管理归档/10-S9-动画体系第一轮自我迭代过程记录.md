本文件记录动画体系第一轮自我迭代中形成的局部实现事实，用于后续回看和整理正式设计说明。

按照 Project Engineering Strategy，本文件不放入 `02_设计说明/` 的稳定设计索引，不作为正式需求规格或长期设计口径的替代物。若后续需要固化为稳定设计，应先整理为可审阅补充方案，经用户确认后再写回 S9 主设计说明。

## 2. 本轮变更边界

本轮只触碰动画子系统内部边界：

- `script/editor/animation_set/AnimationSetCatalog.js`
- `script/editor/animation_set/AnimationSetWorkspace.js`
- `script/editor/animation_set/AnimationSetManagerPage.js`
- `test/animation_set_manager_v1.html`
- `assets/data/animation_catalog_v1.json`
- `test/animation_set_manager.test.mjs`

未改动敌人、角色、技能、战斗主流程等消费模块。

## 3. 本轮实现事实

1. `animation_catalog_v1.json` 的 ready clip 增加只读 `package` 描述，用于表达当前运行时资产包形态仍是 PNG spritesheet。
2. `AnimationSetWorkspace` 增加 `validateAllAnimationSets()`，用于在动画管理器内部汇总全库动画校验结果。
3. 动画集管理器页面增加全库校验入口和校验摘要。
4. 动画集管理器页面增加 catalog 发布状态显示，用于暴露“台账已保存但 catalog 发布失败”的风险。

## 4. 仍需正式化的内容

以下内容尚未进入稳定设计说明：

1. `package` 字段的长期 schema 命名、兼容策略和版本策略。
2. WebP / KTX2 / bundle manifest 等后续压缩输出路线。
3. 全库校验与真实跨模块引用扫描的边界。
4. catalog 发布失败后的重试、回滚或脏状态处理策略。

这些内容需要在后续设计补充方案中集中整理，而不是继续追加临时英文命名的稳定设计文档。

## 5. 第二步补充实现事实：引用扫描

本次继续保持动画子系统内部边界，只新增和调整以下范围：

- `script/editor/animation_set/AnimationReferenceScanner.js`
- `script/editor/animation_set/AnimationSetManagerPage.js`
- `script/editor/animation_set/index.js`
- `test/animation_set_manager.test.mjs`

实现事实：

1. 新增纯扫描器 `AnimationReferenceScanner`，输入为动画 workspace 与外部 JSON 源内容，输出规范化引用结果；扫描器不导入、不修改敌人、角色、技能或战斗主流程模块。
2. 扫描器支持直接 `animationSetRef` / `animationKey` 引用，也支持旧式 `presentation.frameAnimations.*.sheetRef` 反查到动画集 clip。
3. 扫描器显式跳过 `animation_sets_v1.json` 与 `animation_catalog_v1.json`，避免把动画台账或发布 catalog 自身误判为消费方。
4. 管理器页面加载后扫描 `assets/data/player.json` 与 `assets/enemy_packs/current/enemies.json`，并把扫描结果合并显示到引用面板。
5. clip 删除前会检查扫描出的真实消费引用；若仍被消费方引用，则阻止删除和资产清理请求。

仍需正式化的内容：

1. 引用扫描源清单是否应从配置文件声明，而不是由管理器页面内置默认路径。
2. 对技能、特效、关卡脚本等后续消费源的扫描规则与误报策略。
3. 引用扫描结果是否需要进入只读 catalog 或单独生成审计报告。
