## 1. 本文结论

敌人行为决策体系必须拆成两个层次：

1. **一般回合制行为决策框架**：定义回合内一次行动决策如何被描述，包括行动开始、分支判断、业务实施、行动结束、端口、连线、引用和表达式。
2. **本游戏业务应用绑定**：定义上述通用框架如何引用敌人、玩家、技能、Buff、部位、运行时上下文等真实业务数据。

这两个层次不能混在一起。决策框架只创建行为描述结构，不创建战斗内容；业务内容来自已有游戏数据结构和运行时对象。

本文修正 29、30 中不合理的旧口径：

1. 不再把“状态节点”作为通用核心节点。
2. 不在决策框架内保存跨回合状态、上一回合状态或敌人记忆。
3. 不新增独立于业务数据的条件目录、目标目录、主语目录或运行时输入契约。
4. 不在框架中发明 HP、距离、Buff、部位、技能、目标规则等业务字段。
5. 所有业务判断和业务行动都必须通过引用/表达式结构连接到真实业务对象。

如果现有 29、30 与本文冲突，在本文评审通过前，按本文作为下一轮重构口径；评审通过后，再把被接受的结论回写到 29、30 的稳定正文中。

## 2. 设计边界

### 2.1 决策框架负责什么

决策框架负责描述“如何决策”：

1. 图结构。
2. 节点类型。
3. 端口类型。
4. 连线关系。
5. 表达式结构。
6. 引用结构。
7. 画布布局。
8. 静态校验问题。
9. 一次决策调用从入口到出口的流程语义。

### 2.2 决策框架不负责什么

决策框架不负责创造“决策内容”：

1. 不定义敌人有哪些属性。
2. 不定义玩家有哪些属性。
3. 不定义技能有哪些目标、消耗、效果或约束。
4. 不定义 Buff、状态、部位、护甲或距离字段。
5. 不保存上一回合行动。
6. 不保存跨回合状态。
7. 不保存敌人记忆。
8. 不提供独立于业务数据的 `ConditionCatalog`、`TargetResolverCatalog` 或所谓正式 `DecisionRuntimeInputContract`。

如果某个判断需要读取上一回合信息，它也只能读取业务系统已经提供的历史数据引用；决策框架不能自己维护这份历史。

## 3. 第一部分：一般回合制行为决策框架

### 3.1 基本调用模型

敌人决策发生在战斗回合系统的一次行动调用中。

标准流程是：

```text
战斗运行时请求敌人行动
  -> 行动开始
  -> 经过若干分支判断和业务实施节点
  -> 行动结束
  -> 把本次行动决策结果交回战斗运行时
```

下一回合是否再次行动，由战斗回合系统再次调用决策图，而不是由决策图画一条线回到“行动开始”。

因此，决策图里不应该为了表达跨回合循环而画“回到入口”的虚线。跨回合调度是战斗运行时的职责；决策图只描述一次行动调用内部的流程。

### 3.2 核心节点类型

通用框架只需要四类核心节点。

| 节点 | 责任 | 是否业务内容 | 说明 |
| --- | --- | --- | --- |
| 行动开始节点 | 本次决策调用入口 | 否 | 系统节点。没有业务配置，只提供流程起点。 |
| 分支判断节点 | 根据表达式选择后续路径 | 否 | 自身只保存表达式结构；表达式引用的数据来自业务层。 |
| 业务实施节点 | 发出一个业务操作请求 | 否 | 自身只保存业务操作引用；技能、目标、效果等内容来自业务层。 |
| 行动结束节点 | 本次决策调用出口 | 否 | 系统节点。结束本次决策，返回结果给战斗运行时。 |

“状态节点”不属于通用核心节点。所谓状态如果是战斗事实，就应该存在于敌人、玩家、Buff、战斗历史或其他业务数据结构中；决策图只能通过引用/表达式读取它。

### 3.3 辅助节点

为提升可读性，可以允许辅助节点，但它们不能引入新的业务语义。

| 辅助节点 | 允许用途 | 限制 |
| --- | --- | --- |
| 转接节点 | 整理连线、减少交叉 | 不能改变判断结果或行动结果 |
| 注释节点 | 解释一段图 | 不参与运行时 |
| 分组节点 | 组织节点区域 | 不参与运行时 |

早期原型中的 `Merge` 节点不能作为含义不清的默认业务节点继续存在。若确实需要“连线汇合”，应使用明确的转接节点或直接让多条流程线进入同一个后续节点；它不能表达“行动收束”“选择结果”“回合结束”等业务含义。

### 3.4 图对象

通用框架可以拥有这些结构对象：

| 对象 | 框架字段 | 不允许夹带的内容 |
| --- | --- | --- |
| `DecisionGraph` | `id`、`version`、`nodes`、`edges`、`layout` | 敌人属性、技能定义、战斗历史 |
| `DecisionNode` | `id`、`kind`、`label`、`ports`、`config`、`layout` | HP 字段、Buff 字段、技能效果 |
| `DecisionPort` | `id`、`nodeId`、`direction`、`role`、`label` | 具体部位、具体技能、具体目标规则 |
| `DecisionEdge` | `id`、`fromPortId`、`toPortId`、`kind`、`label` | 业务判断结果或业务行动结果 |
| `DecisionExpression` | 表达式树 | 具体属性来源不能由框架发明 |
| `DecisionReference` | 业务引用描述 | 被引用对象必须由业务层解析 |
| `DecisionValidationIssue` | `severity`、`code`、`message`、`nodeId`、`edgeId` | 不能作为业务规则真源 |

`kind`、`direction`、`role` 这类字段是框架结构枚举；它们只描述图怎么运行，不描述游戏里有什么内容。

### 3.5 端口和连线规则

节点连接必须表达清楚流程含义。

1. 行动开始节点只有流程输出。
2. 行动结束节点只有流程输入。
3. 分支判断节点至少有一个流程输入，并有独立的 `true` / `false` 输出端口；不能让两条分支从同一个视觉端口挤出。
4. 业务实施节点至少有一个流程输入和一个流程输出。
5. 数据引用和流程连线要分开表达；读取属性不等于流程跳转。
6. 同一次决策调用中不允许无退出条件的流程环。

编辑器表现上，行动开始和行动结束都是系统节点。它们应该可以被选中、拖拽和查看，但不应该暴露业务配置表单。

## 4. 引用/表达式结构

引用/表达式结构是通用框架与业务应用之间的桥。

分支判断不是一个写死的条件字符串；它应该是一棵表达式树。表达式树中的操作符属于通用逻辑语法，表达式树中的对象、属性、技能、目标和值来源属于业务层。

### 4.1 引用结构

通用引用结构只描述“要引用什么”，不创建被引用对象。

| 引用 | 含义 | 来源要求 |
| --- | --- | --- |
| `EntityRef` | 引用一个实体，如当前行动者、候选目标、战斗对象 | 必须由业务应用提供可选实体槽位 |
| `AttributeRef` | 引用实体或对象上的属性 | 必须来自真实 schema、数据包字段或运行时适配器 |
| `ObjectRef` | 引用业务对象，如 Buff、部位、战斗历史记录 | 必须来自已有业务对象集合 |
| `SkillRef` | 引用技能 | 必须解析到当前敌人的 `skills[]` 以及敌人技能包 |
| `TargetRef` | 引用目标或目标候选 | 必须由技能目标约束和战斗对象解析 |
| `LiteralValue` | 常量值 | 类型必须与被比较引用匹配 |

这些结构允许编辑器提供下拉、筛选和校验入口，但下拉选项必须从真实业务源生成。

### 4.2 表达式结构

表达式结构可以由通用逻辑组成：

1. 比较：`==`、`!=`、`>`、`>=`、`<`、`<=`
2. 逻辑：`and`、`or`、`not`
3. 集合判断：`contains`、`exists`
4. 可用性判断：由业务应用暴露为可调用引用或派生表达式

示例只说明结构，不代表框架内置字段：

```text
AttributeRef(EntityRef(actor.self), realPathFromEnemySchema)
  <=
LiteralValue(0.35)
```

如果真实敌人对象没有该字段，编辑器不能显示这个选项，校验器也不能让它通过。

### 4.3 主语规则

判断和行动都必须有可解释的主语。

1. 分支判断的主语来自 `EntityRef` 或 `ObjectRef`。
2. 技能释放的施放者来自当前行动者引用，不能写死为“敌人”字符串。
3. 技能目标来自 `TargetRef`，并受技能自身目标约束限制。
4. 当主语、属性、技能或目标无法解析时，节点必须进入错误状态。

“我方”“敌方”“对方”“目标”等词只能是 UI 标签，不能是数据真值。数据真值必须解析到具体业务对象。

## 5. 框架对象所有权边界

| 分类 | 可以由决策框架创建 | 必须由业务层提供或解析 | 禁止由决策框架创建 |
| --- | --- | --- | --- |
| 图结构 | 节点、端口、连线、布局、分组 | 无 | 无 |
| 流程语义 | 行动开始、分支判断、业务实施、行动结束 | 无 | 跨回合调度 |
| 表达式语法 | 比较、逻辑、集合判断的结构 | 操作数来源、字段类型、可选对象 | HP、距离、部位、Buff 等具体字段 |
| 业务引用 | 引用格式、引用校验入口 | 实体、属性、技能、目标、状态、历史 | 技能 ID、状态 ID、Buff ID、目标规则 |
| 校验结果 | 错误/警告对象 | 业务合法性判断依据 | 业务规则真源 |
| 运行结果 | 本次决策的流程出口 | 战斗运行时执行、结算、记录 | 上一回合行动、敌人记忆 |

框架可以说“这里引用了一个技能”，但不能说“这里有一个投石技能”。投石技能来自敌人模板的 `skills[]` 和 `assets/data/skills_enemy_v1.json`。

## 6. 第二部分：本游戏业务应用绑定

### 6.1 业务数据事实源

当前敌人行为决策可绑定的业务来源包括：

| 业务对象 | 事实源 | 决策图可做什么 |
| --- | --- | --- |
| 敌人模板 | `assets/enemy_packs/current/enemies.json` | 读取当前敌人的基础字段、技能引用和 `enemyDecision` |
| 敌人技能 | `assets/data/skills_enemy_v1.json` | 解析技能 ID、目标、消耗、效果、requirements |
| Buff 数据 | `assets/data/buffs_v2_7.json` 及当前有效版本 | 解析 Buff 引用、触发、效果和状态表达 |
| 战斗运行时敌人实例 | 战斗系统提供 | 读取当前行动者的运行时属性 |
| 战斗运行时玩家实例 | 战斗系统提供 | 读取候选目标的运行时属性 |
| 部位与护甲 | 角色/敌人/运行时部位结构 | 读取实际存在的部位和护甲数据 |
| 回合上下文 | 战斗系统提供 | 读取当前回合、行动阶段等上下文 |

如果某个字段只存在于旧原型、测试假数据或 UI 硬编码中，它不能成为正式决策条件的来源。

### 6.2 应用绑定层职责

应用绑定层负责把通用引用解析为真实业务对象。

| 绑定能力 | 输入 | 输出 | 约束 |
| --- | --- | --- | --- |
| 实体解析 | `EntityRef` | 当前敌人、玩家、候选目标、上下文对象 | 只能返回运行时真实存在的对象 |
| 属性解析 | `AttributeRef` | 具体字段值和类型 | 字段路径必须来自真实 schema 或适配器 |
| 技能解析 | `SkillRef` | 当前敌人拥有的技能定义 | 必须同时命中敌人 `skills[]` 和技能包 |
| 目标解析 | `TargetRef` | 可选目标集合或单个目标 | 必须受技能 `target`、部位、范围和选择规则限制 |
| 表达式求值 | `DecisionExpression` | true / false / error | 不能在求值时补造缺失字段 |
| 业务行动生成 | `BusinessActionNode` | 战斗运行时可执行的行动请求 | 不能绕过技能要求、消耗和目标合法性 |

### 6.3 分支判断如何绑定业务数据

分支判断节点在框架层只保存表达式。

编辑器应当按以下顺序生成可配置入口：

1. 选择主语：从应用绑定层提供的实体引用列表中选择。
2. 选择属性或对象：从该主语真实可读字段中选择。
3. 选择操作符：按字段类型筛选可用操作符。
4. 选择右值：可以是常量，也可以是另一个业务引用。
5. 校验表达式：确认字段存在、类型匹配、运行时可解析。

例如“HP 小于 35%”不能作为框架内置条件出现。它只能是业务层暴露了真实 HP 字段或 HP 比例派生字段之后，由作者在表达式里选出来的结果。

### 6.4 业务实施节点如何绑定技能

业务实施节点不能把技能卡片简化成一个 `skillId + targetRule` 字符串。

技能行动至少要经过这些绑定：

1. 施放者：来自当前行动者的 `EntityRef`。
2. 技能：来自当前敌人 `skills[]`，再解析到 `assets/data/skills_enemy_v1.json`。
3. 技能约束：来自技能定义中的消耗、requirements、target、actions 和 buffRefs。
4. 目标：由技能目标约束生成可选目标或目标查询。
5. 输出：生成战斗运行时能执行的行动请求。

如果技能要求打部位，编辑器的目标配置就必须来自技能的目标结构和真实部位数据；不能让敌人决策编辑器另写一套目标规则。

### 6.5 历史状态和跨回合数据

决策框架不保存跨回合状态。

如果业务上确实需要判断“上一回合是否做过某事”或“敌人当前是否处于某状态”，正确方式是：

1. 战斗运行时或业务数据结构保存该事实。
2. 应用绑定层把该事实暴露成可引用对象或属性。
3. 分支判断节点通过表达式读取该引用。

错误方式是让决策框架新增 `previousAction`、`currentStateId`、`decisionRuntime.memory` 等自有字段。

## 7. 对当前敌人决策编辑台的具体对应

### 7.1 编辑台主区域

当前编辑台应逐步调整为：

1. 左侧：模板、节点组件、当前敌人技能、业务对象浏览。
2. 中间：从左到右的行为决策图，入口是行动开始，出口是行动结束。
3. 右侧：Inspect 属性栏，按选中对象显示可配置引用和表达式。
4. 顶部：图检查、自动布局、活动图预览、发布检查。

编辑台不应该把一个固定假图当作功能本体。作者必须能基于真实敌人模板和技能包编辑节点、引用和表达式。

### 7.2 节点面板

节点面板应按框架类型组织：

| 面板项 | 说明 |
| --- | --- |
| 行动开始 | 系统节点，每张图一个 |
| 分支判断 | 新增表达式节点 |
| 业务实施 | 新增业务操作节点，具体操作由业务应用绑定 |
| 行动结束 | 系统节点，每张图至少一个 |
| 转接/注释/分组 | 只影响可读性，不影响业务语义 |

不应提供“状态节点”作为通用节点组件。

### 7.3 分支判断 Inspect

选择分支判断节点后，Inspect 至少应提供：

1. 主语选择：来自应用绑定层的实体引用。
2. 左值选择：来自主语真实可读属性或对象引用。
3. 操作符选择：按左值类型筛选。
4. 右值选择：常量或另一个业务引用。
5. 分支出口：明确配置 `true` 和 `false` 的输出端口标签。
6. 校验提示：无法解析的数据源、类型不匹配、运行时不可求值。

这里不能出现框架硬编码的条件类型下拉，除非该下拉只是表达式模板，并且模板展开后仍然指向真实业务引用。

### 7.4 业务实施 Inspect

选择业务实施节点后，Inspect 至少应提供：

1. 行动主语：默认来自当前行动者，但仍然是引用，不是硬编码字符串。
2. 操作类型：由应用绑定层声明，例如释放技能、跳过行动、防御等。
3. 技能引用：当操作类型是释放技能时，只能选择当前敌人 `skills[]` 中存在的技能。
4. 目标配置：由技能 `target` 和真实候选目标共同决定。
5. 约束预览：展示消耗、requirements、目标限制和可能失败原因。
6. 输出路径：业务操作完成后继续走向下一个节点或行动结束。

业务实施节点展示的是“引用和约束摘要”，不是技能定义编辑器。技能定义仍然归技能系统维护。

### 7.5 行动开始和行动结束 Inspect

行动开始和行动结束都是系统节点。

它们可以显示：

1. 节点 ID。
2. 节点角色。
3. 连线状态。
4. 本次图检查结果。
5. 画布布局信息。

它们不应该提供业务字段编辑入口。

## 8. 文档结构调整建议

当前 29、30 都混入了不该混在一起的内容。建议按以下方向整理：

| 文档 | 调整方向 |
| --- | --- |

## 9. 后续落地顺序

## 10. 验收标准

本设计进入实现前，至少应满足以下文档验收标准：

1. 能清楚区分通用框架对象和业务数据对象。
2. 能说明每一类节点拥有什么字段、引用什么业务数据。
3. 能说明分支判断的数据来源，而不是只列条件名字。
4. 能说明业务实施节点如何绑定真实技能和真实目标。
5. 明确禁止决策框架创造业务属性、技能、Buff、部位、目标规则和跨回合状态。
6. 明确旧 29、30 哪些口径需要被修订。
7. 能直接指导下一轮模型和编辑器改造，而不是只停留在概念描述。
