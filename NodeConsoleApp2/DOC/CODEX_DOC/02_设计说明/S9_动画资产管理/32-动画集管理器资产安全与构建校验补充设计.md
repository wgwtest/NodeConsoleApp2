# 动画集管理器资产安全与构建校验补充设计

最后整理时间：2026-06-17

状态：`补充设计 / 部分已落地`

本文补充 `30-动画集管理器(animation_set_manager)-设计说明.md` 和 `31-animation-catalog-interface.md`，记录对动画集管理器主页评审后形成的修订意见。它不替代原设计文档，只约束资产删除、构建校验、响应式布局和发布一致性这几类风险点。

## 1. 评审发现

动画集管理器已经具备对象台账、clip 列表、导入、预览、属性编辑、引用展示和校验报告等基础能力，但当前实现中仍有几类会影响实际使用安全性的缺口。

1. 删除 clip 时，不能把所有 `sourceDir` 都视为可删除资产。旧项目中 `source/character` 下可能存在手工维护的源素材，只有由动画集管理器导入并明确托管的目录，才允许随 clip 删除。
2. 中等宽度屏幕不能隐藏右侧工具区。预览、属性、重新构建、引用和校验报告属于管理器的核心工作面板，隐藏后会让主页只剩选择列表和表格，无法完成完整检查。
3. 构建 spritesheet 前必须校验帧序列的基本一致性。至少要阻止帧尺寸不一致的序列写入正式 sheet，否则后续战斗播放会出现拉伸、裁切或错帧。
4. 台账保存和只读 catalog 发布仍然是两个写入动作。若台账已写入而 catalog 发布失败，运行时消费的数据可能落后一版。
5. 引用展示目前仍以台账内静态引用为主，尚不能在删除或修改前真实扫描敌人、角色、技能、战斗流程中的引用。
6. 预览背景仍缺少透明格、深色、浅色等切换能力，检查透明边缘和特效亮度时不够直观。

## 2. 本次落地修订

### 2.1 删除边界改为所有权驱动

clip 删除默认只删除构建产物：

- `sheetRef`
- `manifestRef`

`sourceDir` 只有在 clip 带有以下托管标记时才会进入删除清单：

```json
{
  "assetManagement": {
    "importedBy": "animation_set_manager",
    "ownsSourceDir": true
  }
}
```

管理器通过本地目录导入创建的新 clip，必须自动写入该标记。历史 clip、手工配置 clip、外部工具生成 clip 若没有 `ownsSourceDir: true`，删除动作不得删除其 `sourceDir`。

确认文案也需要反映这个边界：普通 clip 删除只提示删除构建产物；托管 clip 才提示会同时删除由管理器导入的项目内帧目录。

### 2.2 中等宽度下保留工具区

`1280px` 以下布局不再隐藏右侧面板，而是把右侧工具区移动到全宽下一行，并使用两列紧凑布局呈现预览、属性、操作、引用、校验和 manifest。

这个调整的目标是让主页在笔记本和嵌入式浏览器宽度下仍能完成完整工作流：

1. 选择对象和 clip。
2. 查看真实预览。
3. 修改播放属性。
4. 重新构建。
5. 查看引用和校验结果。

### 2.3 构建前增加帧尺寸校验

spritesheet 写入前，管理器需要加载待构建目录中的全部帧图，并以第一帧为基准校验 `width` 和 `height`。

若任意帧尺寸不一致：

1. 终止本次 sheet 写入。
2. 不调用正式资产写入接口。
3. 将 clip 标记为 `status: "error"`。
4. 将错误原因写入 `clip.buildState.errors`。
5. 保持页面可继续操作，便于用户修正源素材后重新构建。

### 2.4 构建状态显式写回

构建成功时，clip 需要写入：

```json
{
  "buildState": {
    "status": "ready",
    "errors": [],
    "updatedAt": "ISO-8601 timestamp"
  }
}
```

构建失败时，clip 需要写入：

```json
{
  "status": "error",
  "buildState": {
    "status": "error",
    "errors": ["具体错误原因"],
    "updatedAt": "ISO-8601 timestamp"
  }
}
```

这样校验报告和后续批处理不必只依赖顶层 `status` 推断失败原因。

## 3. 修订后的设计口径

动画集管理器的主页不只是“能导入和预览”的工具页，而是动画资产进入正式数据链路前的安全闸口。

因此，后续判断功能是否完成时，应使用以下口径：

1. 删除功能优先保护源素材，只有具备明确托管所有权的目录才允许被自动删除。
2. 构建功能优先保护运行时数据质量，发现帧基础属性不一致时必须失败并记录原因。
3. 页面布局优先保证工作流完整，不应为了窄屏而移除核心检查能力。
4. 发布功能最终应保证台账和 catalog 的一致性，不能长期依赖人工刷新或隐含重试。
5. 引用功能最终应服务删除和修改决策，不能只作为静态展示信息。

## 4. 仍需后续补齐

以下问题本次只记录为后续设计约束，尚未全部落地：

1. 台账保存与 catalog 发布的一致性：需要失败回滚、发布重试、脏状态提示或事务式写入方案。
2. 引用真实扫描：需要从敌人配置、角色配置、技能配置、战斗流程和主程序入口中扫描 `animationSetRef` 与 clip key。
3. 帧命名连续性校验：需要检查帧名排序、编号缺口、重复名和非预期扩展名。
4. 预览背景切换：需要透明格、深色、浅色和自定义背景，便于检查透明边缘、描边和特效亮度。
5. 批量校验入口：需要对当前对象、当前动画集或全库执行统一校验，并汇总错误。

这些项进入后续迭代前，仍应保持当前已落地的删除保护和构建失败保护，不能为了操作便利回退到无所有权删除或静默构建。
